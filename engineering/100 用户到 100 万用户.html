🚀 Web 前端架构演进：从 100 到 1,000,000 用户 ​

当用户量级发生质变时，前端的工作重心会从“功能实现”转向“系统工程”。

1. 资源加载与构建优化 ​

  • 100 用户：单个大 Bundle 即可，基础 Webpack 配置。
  • 1,000,000 用户：
  • 代码分割 (Code Splitting)：首页 JS 严控在 200KB 内。
  • 构建工具：使用 Vite/esbuild 提升速度，Rollup 优化体积。
  • CDN 分发：全站静态资源托管至边缘节点，开启 Brotli 压缩。

2. 运行时性能对比 ​

维度100 用户 (初创期)1,000,000 用户 (成熟期)
首屏策略简单 Loading 动画骨架屏 (Skeleton Screen) + 关键 CSS 内联
数据请求直接 Fetch / AxiosSWR / React Query 缓存，实现秒开
图片工程原图展示动态 WebP 转换 + 响应式尺寸适配

3. 稳定性与监控 (不可或缺) ​

在百万量级下，任何微小的 Bug 都会被放大。

  • 错误捕获：接入 Sentry，实时监控 JS 错误和资源加载异常。
  • 灰度发布：利用 Feature Flags 控制功能开关，先对 1% 用户开放。
  • 容错设计：局部组件崩溃时不影响整站，提供优雅的降级 UI。

4. 实时通信 (WebSocket) ​

  • 连接管理：实现指数退避重连机制，防止百万客户端同时重连压垮服务器。
  • 状态感知：根据页面可见性（Page Visibility）智能挂起或恢复连接。

5. 安全性防范 ​

  • CSP (内容安全策略)：严格限制脚本来源，根除 XSS 注入。
  • SRI (子资源完整性)：确保 CDN 资源未被篡改。
  • 接口防刷：引入人机校验与行为轨迹分析。

总结：100 用户看的是逻辑，100 万用户看的是工程。
